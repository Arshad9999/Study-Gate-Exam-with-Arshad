03 / FOUNDATIONAL TERMINOLOGY & TAXONOMY

Core Definitions & Classifications

Standardized academic definitions and structural classifications essential for conceptual questions:

Candidate Key & Superkey Relational Model

A superkey is any set of attributes that uniquely identifies a tuple. A candidate key is a minimal superkey containing no redundant attributes.

Note: A prime attribute belongs to at least one candidate key.
Lossless-Join Decomposition Normalization

Decomposition of relation R into R_1, R_2 is lossless iff joining the projections recreates exactly R without generating spurious tuples: (R_1 cap R_2) -> R_1 or (R_1 cap R_2) -> R_2 in F+.

Note: Common attribute must be a candidate key of at least one sub-relation.
Conflict Serializability Transactions

A concurrent schedule S is conflict serializable iff it is conflict equivalent to some serial schedule. Tested by checking for cycles in the precedence graph.

Note: Acyclic precedence graph strictly implies conflict serializability.
Two-Phase Locking (2PL) Concurrency Control

Concurrency protocol where transactions acquire locks during a Growing Phase and release locks during a Shrinking Phase without acquiring new locks.

Note: Guarantees conflict serializability; does NOT prevent deadlocks.
B+ Tree Index Invariant Indexing

Balanced search tree where all data records/pointers reside strictly in leaf nodes linked sequentially. Internal nodes store routing keys.

Note: Supports both fast random searches O(log_B N) and contiguous range queries.
Database Normalization Forms Relational Design
  • 1NF (First Normal Form): All column values are atomic; no repeating groups, arrays, or multi-valued attributes.
  • 2NF (Second Normal Form): 1NF + No partial functional dependencies (every non-prime attribute is fully dependent on entire candidate key).
  • 3NF (Third Normal Form): 2NF + No transitive dependencies (for every X -> A, either X is a superkey or A is a prime attribute).
  • BCNF (Boyce-Codd Normal Form): For every non-trivial functional dependency X -> A, X MUST be a superkey; eliminates all redundancy.
Transaction Concurrency & Isolation Levels ACID Properties
  • Read Uncommitted: Lowest isolation; allows Dirty Reads, Non-Repeatable Reads, and Phantom Reads.
  • Read Committed: Disallows Dirty Reads (reads only committed transactions); still allows Non-Repeatable Reads and Phantom Reads.
  • Repeatable Read: Disallows Dirty Reads and Non-Repeatable Reads; allows Phantom Reads (new rows inserted by concurrent transactions).
  • Serializable: Highest isolation; complete execution equivalent to serial schedule; disallows all anomalous read/write concurrency phenomena.
04 / IN-DEPTH SYLLABUS MODULES

Core Theoretical Modules

Comprehensive subject breakdown containing foundational principles, key theorems, and common examination pitfalls.

MODULE 01

ER Modeling, Relational Algebra & SQL Foundations

  • ER to Schema conversion: 1:N relationship is mapped by adding the 1-side primary key as a foreign key on the N-side table.
  • M:N relationship requires a separate junction table containing primary keys of both participating entity sets.
  • Relational Algebra operators: Selection (sigma), Projection (pi), Cartesian Product (x), Natural Join (|><|), Division (/ for "for all" queries).
  • SQL NULL handling: Any comparison with NULL (`x = NULL` or `x <> NULL`) evaluates to UNKNOWN. Use `IS NULL` or `IS NOT NULL`.
Essential Theorem & Principle Codd’s Relational Equivalence Theorem: Relational Algebra and Domain-Independent Relational Calculus are equivalent in expressive query power.
⚠️ GATE Exam Trap & Common Mistake COUNT(*) vs COUNT(col) Trap: `COUNT(*)` counts all rows including those with NULL values; `COUNT(column)` ignores NULL values and counts only rows where that specific column is non-null.
MODULE 02

Functional Dependencies, Normalization & Decomposition

  • Attribute Closure X+: Set of all attributes functionally determined by X under given dependency set F.
  • Candidate Key: Minimal super key whose attribute closure encompasses all schema attributes.
  • Prime attribute: Attribute that belongs to AT LEAST ONE candidate key. Non-prime: belongs to no candidate key.
  • Normal Forms: 1NF (atomic domains); 2NF (no partial dependencies); 3NF (every X->A has X as superkey or A prime); BCNF (every X->A has X as superkey).
Essential Theorem & Principle Lossless Join Condition: A decomposition of relation R into (R_1, R_2) is lossless-join if and only if (R_1 cap R_2) -> R_1 or (R_1 cap R_2) -> R_2 in F+.
⚠️ GATE Exam Trap & Common Mistake 3NF vs BCNF Dependency Preservation: Any relational schema can always be decomposed into 3NF such that it is simultaneously lossless-join AND dependency-preserving. Decomposition into BCNF is always lossless-join, but may NOT preserve dependencies!
MODULE 03

Transactions, Serializability & B+ Tree Indexing

  • ACID properties: Atomicity (all-or-nothing), Consistency (integrity constraints), Isolation (serializability), Durability (WAL logging).
  • Conflict Serializability: Tested by constructing a directed precedence graph. Schedule is conflict serializable iff graph has NO directed cycles.
  • Two-Phase Locking (2PL): Growing phase (locks acquired) and shrinking phase (locks released). Strict 2PL holds exclusive locks until commit/abort.
  • B+ Tree: All keys reside in leaves connected by sequential pointers; internal nodes store routing keys and child pointers.
Essential Theorem & Principle Conflict Serializability Invariant: A concurrent transaction schedule is conflict serializable if and only if its precedence graph contains no directed cycles.
⚠️ GATE Exam Trap & Common Mistake 2PL and Deadlocks: Two-Phase Locking (2PL) guarantees conflict serializability, but it does NOT prevent deadlocks! Transactions under 2PL can still enter circular wait deadlocks.
05 / CANONICAL COMPARISON MATRIX

Conflict Serializability vs. View Serializability

Detailed architectural and mathematical comparison of fundamental contrasting concepts frequently tested in GATE:

COMPARISON DIMENSION Conflict Serializability View Serializability
Equivalence Invariant Schedule S is conflict equivalent to serial S' if all conflicting pairs (R-W, W-R, W-W) have same order. Schedule S is view equivalent to serial S' if initial reads, updated reads, and final writes match.
Class Inclusion Hierarchy Strict subset: Every Conflict Serializable schedule is View Serializable. Superset: Contains all Conflict Serializable schedules plus non-conflict schedules with blind writes.
Validation Complexity Polynomial time O(V + E) by constructing Precedence Graph and checking for cycles. NP-Complete problem in the general case (requires testing against all n! serial orders).
Precedence Graph Test A cycle-free precedence graph is an exact IF AND ONLY IF condition for conflict serializability. A precedence graph cycle does NOT rule out view serializability if blind writes exist.
DBMS Engine Adoption Universally implemented in commercial engines via Two-Phase Locking (2PL) protocols. Impractical for live transaction lock managers due to NP-complete validation overhead.
GATE Examination Pitfall Two operations conflict iff they belong to different transactions, access the SAME data item, and at least one is a WRITE. If a schedule contains NO blind writes, View Serializability is IDENTICAL to Conflict Serializability.
06 / MATHEMATICAL FORMULATION

Relational Normal Forms & Lossless Decomposition

Database Normalization 
Decomposition R into (R1, R2) is Lossless-Join if and only if:
  (R1 cap R2) -> R1 in F+  OR  (R1 cap R2) -> R2 in F+
(i.e., common attribute must be a Super Key of at least one relation)

Normal Form Hierarchy:
  1NF: Atomic attribute domain values.
  2NF: 1NF + No partial dependency (Non-prime attribute -> part of candidate key).
  3NF: 2NF + For every X -> A, either X is a Super Key OR A is a prime attribute.
  BCNF: For every X -> A, X MUST be a Super Key.
