03 / FOUNDATIONAL TERMINOLOGY & TAXONOMY

Core Definitions & Classifications

Standardized academic definitions and structural classifications essential for conceptual questions:

Process Control Block (PCB) Process Management

Kernel data structure storing execution context of a process: PID, program counter, register values, memory limits, and open file lists.

Note: Context switching saves state to the current PCB and loads the next PCB.
Counting Semaphore Synchronization

Integer synchronization primitive initialized to S. wait(S) decrements S and blocks if S < 0; signal(S) increments S and unblocks a waiting process.

Note: Binary semaphore (mutex) takes values strictly in {0, 1}.
Deadlock & Banker’s Safety Deadlocks

Deadlock occurs when processes in a set are waiting for events that only other processes in the set can trigger. Banker’s algorithm grants resources only if a safe sequence exists.

Note: Four Coffman conditions: Mutual Exclusion, Hold & Wait, No Preemption, Circular Wait.
Translation Lookaside Buffer (TLB) Memory Paging

Fast associative hardware cache storing recently translated Virtual Page Number to Physical Frame Number mappings.

Note: TLB hit avoids memory lookup to page tables: EAT = t_TLB + t_mem + (1 - H)*2 t_mem.
Thrashing Virtual Memory

Pathological condition where the CPU spends more time swapping pages between RAM and disk than executing instructions.

Note: Remedied using the Working Set Model or Page Fault Frequency regulation.
CPU Scheduling Policy Taxonomy Process Scheduling
  • First-Come First-Served (FCFS): Non-preemptive; simple FIFO queue; suffers from severe Convoy Effect for CPU-burst jobs.
  • Shortest Job First (SJF / SRTF): Minimizes average waiting time; SRTF is preemptive variant; prone to starvation for long bursts.
  • Priority Scheduling: Dispatches highest priority job; preemptive or non-preemptive; resolved starvation via Aging.
  • Round Robin (RR): Preemptive time-sliced scheduling; quantum q too large degenerates to FCFS; too small causes high context-switch overhead.
  • Multi-Level Feedback Queue (MLFQ): Dynamic priority queues adapting to process burst history (I/O-bound prioritized over CPU-bound).
Deadlock Mitigation Strategies Resource Allocation
  • Deadlock Prevention: Disallows at least one of the 4 Coffman conditions (Mutual Exclusion, Hold & Wait, No Preemption, Circular Wait).
  • Deadlock Avoidance (Banker's Algorithm): Dynamically verifies whether granting a resource keeps system in a Safe State (exists safe sequence).
  • Deadlock Detection & Recovery: Periodically executes cycle detection on Resource Allocation Graph (RAG); terminates processes or preempts resources.
  • Ostrich Algorithm: Ignores the problem assuming deadlocks occur rarely; standard choice for general-purpose desktop operating systems.
04 / IN-DEPTH SYLLABUS MODULES

Core Theoretical Modules

Comprehensive subject breakdown containing foundational principles, key theorems, and common examination pitfalls.

MODULE 01

Process Control, Threading Models & CPU Scheduling

  • Process vs Thread: Threads share code, data, and open files of the parent process, but retain private program counter and stack.
  • System call `fork()` duplicates calling process. Returns 0 to child, positive PID to parent, -1 on failure.
  • Scheduling metrics: Turnaround Time = Completion - Arrival. Waiting Time = Turnaround - Burst Time.
  • Shortest Remaining Time First (SRTF) is optimal for minimizing average waiting time among all scheduling algorithms.
Essential Theorem & Principle SRTF Turnaround Optimality: Shortest Remaining Time First scheduling produces the provably minimum average waiting time across any set of processes with known burst times.
⚠️ GATE Exam Trap & Common Mistake Fork() Power of Two Trap: A sequence of n successive `fork()` calls without conditionals creates exactly 2^n - 1 child processes, resulting in 2^n total concurrent processes.
MODULE 02

Concurrency, Classical Synchronization & Deadlocks

  • Critical Section 3 criteria: (1) Mutual Exclusion, (2) Progress, (3) Bounded Waiting.
  • Counting Semaphore S: wait(S) decrements S and blocks if S < 0; signal(S) increments S and wakes a blocked process.
  • Deadlock Coffman conditions: Mutual Exclusion, Hold and Wait, No Preemption, Circular Wait.
  • Banker’s Algorithm: Avoids deadlock by granting requests only if the resulting system state remains safe.
Essential Theorem & Principle Single-Instance RAG Deadlock Equivalence: In a Resource Allocation Graph where every resource type has exactly one instance, a directed cycle is necessary AND sufficient for deadlock.
⚠️ GATE Exam Trap & Common Mistake Multi-Instance Deadlock Fallacy: If resources have multiple instances, a cycle in the Resource Allocation Graph does NOT imply deadlock! It is a necessary condition, but not a sufficient condition.
MODULE 03

Memory Paging, TLB Translation & Page Replacement

  • Paging: Virtual Address = Page Number (p) | Page Offset (d). Physical Address = Frame Number (f) | Page Offset (d).
  • Page Table Size = Number of Pages * Page Table Entry (PTE) size.
  • Translation Lookaside Buffer (TLB): Associative hardware cache for fast virtual-to-physical address mapping.
  • Page Replacement: Belady’s Anomaly occurs in FIFO where increasing frames increases page faults. LRU and Optimal are stack algorithms immune to Belady’s anomaly.
Essential Theorem & Principle Stack Algorithm Invariance: Any page replacement algorithm satisfying the inclusion property (the set of pages in memory for m frames is a subset of the pages for m+1 frames) can never exhibit Belady’s anomaly.
⚠️ GATE Exam Trap & Common Mistake Multi-Level Page Table Size Trap: Multi-level paging reduces physical memory consumption because unallocated virtual memory ranges do NOT require second-level page tables to be created in RAM!
05 / CANONICAL COMPARISON MATRIX

Paging vs. Segmentation

Detailed architectural and mathematical comparison of fundamental contrasting concepts frequently tested in GATE:

COMPARISON DIMENSION Paging (Fixed-Size Partitioning) Segmentation (Variable-Size Logical Blocks)
Memory Block Allocation Memory divided into fixed-size physical frames and virtual pages (e.g. 4 KB). Memory divided into variable-size segments reflecting logical program structure.
Programmer Visibility Completely transparent (invisible) to programmer; managed by hardware MMU. Visible to programmer/compiler; addresses specified as (Segment Number, Offset).
Fragmentation Profile Suffers from Internal Fragmentation (in final page); ZERO external fragmentation. Suffers from External Fragmentation (scattered unusable memory holes); ZERO internal fragmentation.
Address Translation Hardware Page Table mapping Virtual Page Number (VPN) to Physical Frame Number (PFN). Segment Table containing Segment Base Address and Segment Limit (length bound).
Protection & Sharing Uniform protection bits (Read/Write/Execute) applied per page frame. Naturally aligns with modular program units (functions, symbol tables) for clean sharing.
GATE Examination Pitfall Page offset bits are never checked for overflow (offset naturally wraps to next frame). In segmentation, if Offset >= Limit, a CPU trap (Segmentation Fault) is immediately triggered!
06 / MATHEMATICAL FORMULATION

Banker's Algorithm & Effective Paging Time

Systems & OS 
Banker's Safety Algorithm Check:
  Need[i][j] = Max[i][j] - Allocation[i][j]
  If Need_i <= Work:
     Work = Work + Allocation_i
     Finish[i] = true
  Safe Sequence exists <=> all Finish[i] == true

Two-Level Paging with TLB:
  EAT = Hit_TLB * (t_TLB + t_mem) + (1 - Hit_TLB) * (t_TLB + 2 * t_mem + t_mem)
      = t_TLB + t_mem + (1 - Hit_TLB) * 2 * t_mem
